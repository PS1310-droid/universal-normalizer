The Template Engine

Before the API can clean your data, it needs a target schema. You have two options: pass a single template name like shopify_customer and let the API load the full schema for you, or send your own custom master_keys array for any database. I maintain pre-built, versioned, industry-standard schemas so the common cases stay lightweight.

shopify_customer salesforce_lead hubspot_contact mailchimp_member 
{
  "template_name": "shopify_customer",
  "messy_data": { ... }
}
02_

The Steamroller

Now that the API has a target, it looks at your messy payload. Real APIs send deeply nested nightmares: objects inside objects, arrays of objects. Before any matching happens, the Steamroller recursively flattens your data. A key buried at customer → location → city becomes customer_location_city. The unpredictable nesting gets destroyed to create a flat, predictable surface.

Input
{ "customer": { "location": { "city": "Gotham" } } }
Output
{ "customer_location_city": "Gotham" }
03_

Exact Matcher

With a flat payload and a clean template, the API does the cheap work first. It strips casing and punctuation to find deterministic matches. Why pay an LLM to figure out that First-Name is FirstName? The easy stuff gets mapped for free, in milliseconds, with zero hallucination risk.

"First-Name" → strips to "firstname" → matches "FirstName"? Yes → mapped. Free.
"tele_phone" → strips to "telephone" → matches "PhoneNumber"? No → goes to LLM
04_

Semantic Fallback & Confidence Gate

Only the keys that failed the code match get routed to the LLM. The model scores the semantic equivalence of what remains. If the confidence is above 85%, the field is auto-mapped into your clean output. If it scores lower, the API safely flags it for human review with the suggested match attached. Your team decides, not the model. No hallucinated data in your production database.

"ready_to_use": {
  "FirstName": "Bruce"
}

"flagged_for_review": {
  "PhoneNumber": {
    "suggested_match": "tel",
    "confidence_score": 61
  }
}

Payload Formats

When calling /normalize/auto, you must provide the raw JSON object you want cleaned as messy_data. You also need to tell the normalizer what your target schema looks like. You have two options:

Option A: Using a Template

Pass template_name with the exact name of a verified template. The API loads the full schema for you.

{
  "template_name": "shopify_customer",
  "messy_data": { ... }
}

Option B: Custom Master Keys

Pass your own array of strings as master_keys to define any schema on the fly. Works with any database.

{
  "master_keys": ["FirstName", "PhoneNumber"],
  "messy_data": { ... }
}

Manual Mode

Already know exactly which fields map to what? Skip the LLM entirely. POST a schema_map object and the API applies it directly. No model calls, no confidence scores, instant output. Use this in production pipelines where the schema is stable and speed matters.

POST /normalize/manual
curl -X POST https://yourdomain.com/normalize/manual \
  -H "Content-Type: application/json" \
  -d '{
    "schema_map": {
      "FirstName": "f_name",
      "PhoneNumber": "tel"
    },
    "messy_data": {
      "f_name": "Bruce",
      "tel": "555-1234"
    }
  }'
